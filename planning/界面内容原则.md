# 界面内容原则

2026-11-03用户明确要求，作为后续迭代的长期约束。

1. 所有用户可见页面、弹窗、提示、空状态和导出内容均面向实际岗位任务，呈现最终产品的业务结果。不得出现演示、原型、模拟数据、样本页面、待开发等开发过程语义。
2. 工程边界、数据准备方式、接口未接入、浏览器存储与后端实施说明放在README、设计交接文档或页面台账中，不能混入普通业务页面。
3. 不删去必要的业务事实：待发送不等于发送成功，缺少因子不等于零排放，部分核算不等于完整总量。通过准确的业务状态说明结果，不为视觉完整而编造成功状态。
4. 每条说明须帮助用户理解范围、判断结果、填写字段或执行下一步。重复标题、泛化宣传口号、不增加信息的页脚予以删除；详细规则可折叠，在相关操作处保留必要提醒。
5. 装饰图形和品牌视觉可以保留，但不能假装成精确地图、在线状态或业务证据。不得擅自补造ICP备案号、版权主体、认证标识或监管背书。
6. 保持现有导航、表格、间距、颜色和状态语义一致。调整视觉体系以改善具体任务为目标，不因使用某个组件库而强行迁移技术栈。

本轮处理：去除业务页页脚与侧栏口号、登录表单底部重复口号；缩短各页面副标题；系统管理页不再使用通用宣传副标题；移出操作记录中的浏览器实现说明；上报文案聚焦状态和处理动作；因子状态与历史重算说明改为可展开帮助；日期改为北京时间实际日期。
